AI assistants are good at writing SQL and bad at knowing whether it actually runs. Is || string concatenation in MySQL? Does that window function work in SQL Server 2017? Does PostgreSQL 19 still accept this syntax? The model guesses, you copy the query into a terminal, and only then do you find out. Today I launched an MCP server for sqlize.online , the online SQL sandbox I've been running for several years. Now Claude, Cursor, VS Code Copilot and any other Model Context Protocol client can run SQL themselves, on real database engines, and show you the actual result instead of a guess. It's listed in the official MCP Registry as online.sqlize/sqlize . What it gives your assistant 36 real engines and versions, not an emulator: MySQL 8.0–9.7, MariaDB 10–12, PostgreSQL 16–19 (with PostGIS), SQL Server 2017–2025, Oracle 21c and 26ai, SQLite, DuckDB, ClickHouse, Firebird and RedDatabase. A fresh database for every call. Each run starts with an empty database that is dropped afterwards, so the assistant can create tables, insert data and experiment without breaking anything. Preloaded sample databases: Sakila, AdventureWorks, Oracle HR, an airline bookings demo, PostGIS NYC data, NYC taxi trips in DuckDB and more. They are read-only, and the assistant can look up their schema before writing queries. A link for every result. Each run returns a sqlize.online link where you can open the script, edit it, run it again and share it. No setup: no account and no API key. Connect Claude Code claude mcp add --transport http sqlize https://api.sqlize.online/mcp claude.ai: Settings → Connectors → Add custom connector → https://api.sqlize.online/mcp Cursor ( ~/.cursor/mcp.json ), Windsurf and other clients: { "mcpServers" : { "sqlize" : { "url" : "https://api.sqlize.online/mcp" } } } VS Code ( .vscode/mcp.json ): { "servers" : { "sqlize" : { "type" : "http" , "url" : "https://api.sqlize.online/mcp" } } } Tools Tool What it does list_databases Engines and versions, with the sql_version id to pass to the other tools run_sql Runs a script in a fresh database and returns every result set as a table, errors per statement, and a sqlize.online link describe_database Tables, columns and foreign keys of a preloaded sample database create_share_link Saves a script without running it and returns its sqlize.online link What it looks like Ask the assistant something like "Rank customers by total order amount, check it on PostgreSQL 19" . It writes the script, including the test data, and calls run_sql . This is the real answer from the server: PostgreSQL 19: ran 3 statements. Result 1: 2 rows | customer | total | place | | --- | --- | --- | | Ann | 165 | 1 | | Bob | 80 | 2 | Open on sqlize.online: https://sqlize.online/sql/psql19/95b720bc118059606dbdb8e1bb6068b9 Now the case where running the query really matters. In PostgreSQL, Oracle and SQLite 'abc' || 'def' gives abcdef . Ask the assistant to check the same expression on MySQL 8.0: MySQL 8.0: ran 1 statement. Result 1: 1 row | concat_test | | --- | | 0 | No error, just a silent 0 : by default MySQL reads || as logical OR. A model that only writes SQL would happily hand you that query. A model that runs it sees the 0 and switches to CONCAT() . What it's good for Checking a query across engines and versions before it goes into a migration or a multi-database product. Learning SQL: ask "why does this return nothing?" and the assistant can try variations and show you the real output. Reproducing bugs with a minimal script and a shareable link to paste into an issue. Comparing dialects: the same task in MySQL, PostgreSQL and SQL Server side by side. Interview and teaching examples that you know actually work. Limits It's a free public sandbox, so there are fair-use limits: up to 200 rows per result set and 30 KB per answer, with longer output cut and marked; up to 100 KB of SQL per call; 100 requests per 10 seconds per IP; nothing persists between calls, and the sample databases are read-only. The server speaks Streamable HTTP (stateless JSON, protocol versions 2025-03-26 to 2025-11-25). You can also try the tools by hand on the API page . If you're learning SQL, the same engines power the practice tasks and the playground on SQLtest.online . Try it and tell me what you'd want next: more engines, persistent databases, query plans?
