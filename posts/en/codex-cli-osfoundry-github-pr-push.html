"push only its dedicated branch"를 git으로 풀면 osFoundry 서버 쪽 프로바이더 push 코드는 공개돼 있지 않다. 대신 데스크톱 앱이 직접 하는 push, 그러니까 GitNest의 Push Change Set Branch 버튼 뒤에 있는 gitnest_desktop.rs 의 gitnest_push_change_set_branch 는 볼 수 있다. 퍼블리케이션 프리플라이트가 돌려준 값을 받아서 이 순서로 처리한다. origin 의 fetch URL과 push URL을 읽고, 둘이 다른 저장소를 가리키거나 프리플라이트가 말한 프로바이더, 오너, 저장소가 아니면 거절한다. 브랜치가 정확히 osfoundry/change-set-<id> 이고 <id> 가 UUID인지 본다. 마커가 정확히 GitNest-Change-Set: <id> 인지 본다. 합성 OID가 4~64자 16진수인지 보고, git cat-file -e <oid>^{commit} 으로 실제로 있는지 확인한다. git update-ref refs/heads/<branch> <oid> <old> 를 돌린다. <old> 는 읽었을 때 ref가 가리키던 값이고, 없었으면 빈 값이다. refspec 하나만 push한다. git push origin refs/heads/<branch>:refs/heads/<branch> . 스크립트에서는 GitHub 대신 bare 저장소를 하나 세워서 이걸 그대로 재현했다. 클론 쪽에는 오너가 아직 push 안 한 게 두 개 있다. 로컬 브랜치 wip/secret-pricing , 그리고 release/2.4 에 올라간 커밋 하나. 합성 커밋은 워크트리 없이 만든다(임시 인덱스, hash-object , update-index --cacheinfo , write-tree , commit-tree ). remote refs before: 3 (dana/refactor-cart, main, release/2.4) `git push --all` would change 2 remote refs: ['release/2.4', 'wip/secret-pricing'] explicit refspec push changed 1 ref: osfoundry/change-set-5b0c2e8e-3f6a-4d2b-9a71-0c4e9d1f7a23 -> 73e59f27bc4f untouched: True;
